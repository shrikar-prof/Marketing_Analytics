Every engineered feature, the raw columns it is built from, why it exists, and whether the models use it. Checks use the training split only (5,634 customers). Associations with churn are not causes.

Rule for keep/drop (fixed before results): binary feature KEEP if the churn-rate gap is at least 5 points and both groups have at least 100 training rows; other features KEEP if |Spearman rho| >= 0.10; then drop a feature if it is a near-duplicate (|rho| >= 0.95) of an earlier kept one.

## Raw columns used as model inputs

Categorical (one-hot encoded inside the model pipeline): gender, Partner, Dependents, PhoneService, MultipleLines, InternetService, OnlineSecurity, OnlineBackup, DeviceProtection, TechSupport, StreamingTV, StreamingMovies, Contract, PaperlessBilling, PaymentMethod. Numeric: SeniorCitizen, tenure, MonthlyCharges.

## Columns deliberately left out

| column | reason |
|---|---|
| customerID | identifier; kept only to join scores back |
| Churn | text copy of the target |
| tenure_band, monthly_charge_band | reporting bands built from tenure and MonthlyCharges |
| TotalCharges, avg_monthly_spend, price_vs_history_pct | built from lifetime billing; timing relative to exit is unknown, so they may carry the outcome (see leakage check in notebook 02, section 3) |
| has_internet | same information as InternetService |
| n_addons, n_protection_addons | counts of columns already present (n_protection rebuilds the second inside the pipeline) |

## Notes

- `price_resid` is fitted (a regression on training rows). Inside the model it is refitted on the training part of every cross-validation fold. The column stored in features.parquet is fitted on the whole training split for documentation only.
- `SeniorCitizen` and `gender` are raw inputs. `gender` shows no churn link in the exploration. `SeniorCitizen` does; check the policy before using an age-related field to decide who gets an offer.
